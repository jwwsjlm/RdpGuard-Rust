# RdpGuard v0.3.2 在线安装与历史日志监控设计

日期：2026-08-05

## 目标

RdpGuard v0.3.2 提供一条可直接粘贴到 Windows PowerShell 的在线安装命令，并把终端监控器简化为按需读取历史日志的工具。

后台 `RdpGuard` 服务继续常驻并执行自动封禁。`rdpguard-monitor.exe` 仅在用户手动启动时运行，不自动刷新，也不读取当前 TCP 连接。

## 用户入口

README 的首选安装方式为：

```powershell
& ([scriptblock]::Create((irm "https://github.com/jwwsjlm/RdpGuard-Rust/releases/latest/download/Install-RdpGuard-Online.ps1")))
```

该命令从最新正式 GitHub Release 读取在线引导脚本。手动下载 ZIP 并运行 `Install-RdpGuard.ps1` 的方式继续保留，作为离线安装和故障排查入口。

## 在线安装架构

新增独立脚本 `Install-RdpGuard-Online.ps1`。它只负责获取并验证发布包，实际安装仍交给发布包内已经过测试的 `Install-RdpGuard.ps1`，避免维护两套服务安装逻辑。

执行流程：

1. 确认运行环境为 Windows PowerShell，并启用 TLS 1.2。
2. 通过 GitHub API 查询 `jwwsjlm/RdpGuard-Rust` 的最新非草稿、非预发布 Release。
3. 验证标签符合 `v<主版本>.<次版本>.<修订版本>`，并定位名称严格匹配该标签的 ZIP 以及 `SHA256SUMS.txt`。
4. 在系统临时目录下创建随机子目录并下载两个文件。
5. 严格解析校验文件，只接受目标 ZIP 对应的 64 位十六进制 SHA-256。
6. 使用 `Get-FileHash` 计算下载文件哈希并进行不区分大小写的完整比较。
7. 校验成功后解压 ZIP，确认其中存在服务程序、监控程序、默认配置和本地安装器。
8. 通过本机 Windows PowerShell 运行本地安装器；本地安装器负责请求 UAC、停止旧服务、复制文件并启动新服务。
9. 检查安装器退出码；无论成功或失败，都在 `finally` 中删除临时目录。

在线安装不要求二次确认。用户取消 UAC、网络请求失败、Release 数据异常、文件缺失、哈希不一致、解压失败或本地安装失败时，脚本立即停止，显示明确错误，并且不会执行未校验的发布包。

此校验可发现下载损坏或文件不匹配。脚本和校验文件均来自同一个 GitHub Release 信任边界；它不等同于代码签名，README 会如实说明这一点。

## 发布方式

Release 工作流除现有 ZIP 和 `SHA256SUMS.txt` 外，再上传 `Install-RdpGuard-Online.ps1` 作为独立附件。因此 `releases/latest/download/Install-RdpGuard-Online.ps1` 始终指向最新正式版脚本，不依赖 `main` 分支内容。

发布 ZIP 内也包含该脚本，方便用户审查和归档。版本升级为 `0.3.2`，更新 `Cargo.toml`、锁文件、变更记录、测试摘要和文档，并创建 `v0.3.2` 标签触发正式发布。

## 历史日志监控器

`rdpguard-monitor.exe` 保留两个页面：

- IP 历史概览：IP、登录尝试、成功、失败、RdpGuard 防护失败数、封禁状态、解封时间和最后活动时间。
- 登录事件：本地时间、成功或失败、IP、用户名和事件 ID。

删除“当前连接”页面、TCP 会话采集和相关 Windows IP Helper API 依赖。监控器启动时读取一次所选范围的数据；保持打开时不启动刷新计时器。只有用户按 `r` 或切换时间范围时才重新查询。

保留的操作：

- `Tab` / `Shift+Tab`：切换两个页面。
- `1` / `2` / `3` / `4`：选择最近 10 分钟、1 小时、24 小时或 7 天，并按需重新读取。
- `r`：手动重新读取当前时间范围。
- 方向键：滚动。
- `q` / `Esc`：退出并恢复终端状态。

Security `4624/4625` 与 RdpCoreTS `140` 继续分开统计。Security 日志不可访问时显示警告，RdpCoreTS 历史和当前封禁状态仍可显示。单个事件源仍限制最多处理 50,000 条事件。监控器不保存用户名或登录历史，也不调用防火墙、封禁、解封或状态写入接口。

## 测试策略

在线安装先增加会失败的测试，再实现脚本。测试覆盖：

- 在线脚本存在于 Release 附件和 ZIP 清单。
- 只使用固定 GitHub 仓库，严格匹配正式版本标签和资源名称。
- 哈希正确时允许进入安装，哈希缺失、格式错误或不一致时停止。
- 临时目录在成功和失败路径都会清理。
- 调用本地安装器并传递其非零退出码。
- PowerShell 语法解析通过。

监控器测试覆盖：

- 只渲染 IP 历史概览和登录事件两个页面。
- 不再存在当前连接页面或 TCP 查询调用。
- 等待期间不会自动刷新；启动、按 `r` 和切换时间范围会重新读取且不会累计旧结果。
- 两页切换、滚动、窄窗口、中文显示和异常退出终端恢复继续有效。
- 后台服务的封禁、解封及默认策略回归测试保持通过。

最终验证包括 Rust 全部测试、格式检查、Clippy、Release 构建、PowerShell 语法、工作流检查和发布资产核对。GitHub Release 完成后下载正式附件，验证 ZIP 哈希、文件清单以及两个 EXE 的 `0.3.2` 版本。

## 非目标

- 不建立自定义短域名或额外下载服务器。
- 不让在线脚本直接实现服务安装逻辑。
- 不增加后台 GUI、托盘程序或日志持久化数据库。
- 不停止或削弱负责自动封禁的 `RdpGuard` 后台服务。
- 不保留当前连接页面或实时 TCP 会话监控。
